# Google出力のうちCCのものだけを文字列化するなら

- 日付: 2026-08-14 07:42 JST
- 前提: 対象はCreative Commons（またはPDM）と確認できた作品。Googleの検索画面そのものや、許諾のない歌詞パネルは対象外。

## 結論

Googleの描画結果をOCRしない。検索は発見だけに使い、文字列化はCCの原文URLから行う。

```text
検索（発見）
  -> 結果の正規URLと権利表示を読む
  -> 原文ホストへ行く
  -> license URL / rel=license / SPDX を機械確認
  -> 原文を text 化
  -> attribution と source hash を一緒に保存
```

## なぜOCRしないか

- GoogleのSERP、知識パネル、歌詞ボックスの著作権はGoogleおよびそのライセンサー側。画面がCCに見えても、表示UIはCC作品本体ではない。
- レイアウトはA/Bで変わる。キャプチャは再現できない。
- Chromeのクローム（ロゴ、広告、関連質問）が混ざる。
- 検出回避のための人間偽装は、この経路の一部にしない。

## 発見

公式の検索APIで usage rights を指定する。Web UIのスクレイピングは使わない。

取るもの:

- `link`（原文URL）
- `title`
- 可能なら `rights` / ライセンス名
- snippet は発見用。本文の代用にしない

snippetを「CC本文」として保存しない。短い引用ですら、原文ライセンスのattribution条件を満たさないことがある。

## 権利確認（fail-closed）

原文ページで次のいずれかが機械的に読めるときだけ通す。

- `rel=license` または明示されたcreativecommons.org / SPDX URL
- CC0 / PDM の公式バッジまたは権利文
- 作品単位のライセンス（サイトフッタの包括文だけは不足）

次は通さない。

- 「検索結果に出た」
- 「Googleが歌詞を出した」
- 「見た感じフリー」
- ライセンスページへ辿れない画像OCR

BY系は作者名、タイトル、ライセンスURL、出典URLを必須で残す。SA系は派生のライセンス継承も記録する。NC/NDは研究hashでも本文複製を避ける。

## 文字列化の優先順

1. 原文HTMLの本文ノード（記事本文、歌詞がCCならその要素）。ナビ・広告・関連を捨てる。
2. 原文PDFのtext layer。
3. 原文が画像作品で、その画像自体がCCのときだけOCRする。Googleのスクショではない。
4. どれも失敗したら `unavailable`。別サイトへfallbackしない。

OCRするなら:

- 入力は原文ホストの画像
- 言語を固定（日本語ならjpn+eng）
- 認識textと画像hash、OCRエンジン、バージョンを残す
- 信頼度が低い行は本文に混ぜず `ocr_uncertain` にする

## RenCrowに載せるなら

歌詞本文はWebから複製しない正本は維持する。CC0 / PDM / 明示許諾だけが `full_text` になれる。それ以外はURL、license URL、attribution、content hash、非復元Syntax。

Google歌詞パネルはこの条件を満たさない。LyricFindの曲名一覧はmetadataであり、本文ライセンスではない。
