# コンテキスト圧縮前の情報整理 — 外部報告用メモ（2026年9月22日）

## 文書情報

- 作成日時: 2026年9月22日 12:45 JST
- 目的: 長時間のAIコーディング作業において、圧縮前に整理すべき情報、保持すべき情報、改善の適用境界を外部へ説明する。
- 引き継ぎ元: 利用者との圧縮改善に関する対話。「削減対象の全一覧」を資料として保存する依頼に基づく。
- 位置づけ: 改善方針の整理メモ。実装済み機能、OpenAI公式仕様、全モデルで再現確認済みの不具合一覧ではない。既存の運用指示を自動的に置き換えるものでもない。
- 契約上の制約: OpenAI提供のCodexを利用し、Codex本体・内部の圧縮処理は改変しない。モデルの能力、必要な安全・認証・データ保全の保証を削減しない。
- 根拠: 今回の対話と既存のQwen観測記録。新たな調査・比較実験は本メモ作成時に行っていない。

## 結論

コンテキスト圧縮の前に、現在有効な指示と過去の作業履歴を整理する工程が必要である。「最新の指示を優先する」と追記するだけでは、撤回済み・完了済みの命令が現行指示として残り、再実行や方針混同を誘発する可能性がある。

整理後の作業用情報は、現在有効な指示、未完了の要求、有効な判断・成果、証拠の参照、次の作業を中心に構成する。削減は単なる文字数削減ではなく、必要な意味と作業継続性を維持するために行う。

本書でいう「削除」はモデルへ渡す作業用情報から外すことを意味する。原本、監査証跡、必要な履歴を消すことではない。また、記録ファイルを編集しても、すでにCodexの会話履歴へ入った内容が自動的に消えるとは限らない。

## 圧縮前の削減対象一覧

以下は今回整理した対象一覧であり、すべてのシステムで発生する項目や、任意の履歴削除機能の存在を示すものではない。

| 対象 | 圧縮前の扱い | 残すもの |
|---|---|---|
| 撤回・置換された指示 | 現行指示から削除する | 現在有効な指示。再混同しやすい場合だけ短い失効注記 |
| 完了した単発の指示 | 命令文を削除し、結果へ置き換える | 完了結果、証拠の参照、再検証が必要になる条件 |
| 重複する指示・制約 | 一つに統合する | 正本と適用範囲 |
| 矛盾する指示 | 明示的な訂正・優先順位に従って整理する | 現行指示。解消できない矛盾は未解決として明記 |
| 期限切れ・条件不成立の指示 | 現在の作業対象から外す | 再び適用される条件があれば、その条件 |
| 古い計画・採用しなかった案 | 詳細を外す | 現行計画。再提案を防ぐために必要な却下理由 |
| 完了工程の細かな手順 | 結果に置き換える | 成果物、受入状態、後続への影響 |
| 途中経過・定期的な進捗報告 | 最新状態に統合する | 完了・未完了・阻害要因 |
| 古い状態のスナップショット | 現在状態に置き換える | 確認時刻、対象環境、未確認部分 |
| 解消済みのエラーと再試行ログ | 経過の全文を外す | 原因、対処、修正確認、必要な再発防止事項 |
| 棄却済みの仮説・探索の行き止まり | 検討過程を外す | 棄却理由と、それを覆す条件 |
| 長い推論・同じ判断の繰り返し | 管理可能な記録を結論と根拠に要点化する | 判断理由、不確実性、重要な選択肢。非公開のモデル内部情報を取得・編集する趣旨ではない |
| 取得済みソースコードの全文 | 必要な契約・変更箇所に限定する | ファイル参照、対象revision、重要な挙動 |
| 大量の検索結果・一覧 | 関連箇所だけに絞る | 採用した参照先、検索範囲と未発見の意味 |
| 生のテスト・build・実行ログ | 結果と必要な失敗箇所に要点化する | 対象、終了状態、証拠パス、適用限界 |
| 同一ファイル・ログの重複取得 | 重複を削除する | 最新の有効な内容、必要なら変更差分 |
| 中間差分・修正前コード・一時生成物 | 現行成果物へ集約する | 最終差分、未適用変更、必要なrollback情報 |
| 繰り返された仕様・ツール説明 | 管理可能な重複を削除する | 正本の参照と、現在の作業に必要な契約。Codex提供の定義や必要な制約を勝手に削らない |
| 子エージェントや外部ツールの長い報告 | 検証済み所見に集約する | 成果、証拠、未検証事項、未解決点。報告を検証済み事実へ格上げしない |
| 終了したプロセス・セッションの操作情報 | 不要なIDや操作履歴を外す | 動作中の処理、後片付け、結果取得に必要な情報 |
| 古い圧縮要約・重ね書きした引き継ぎ | 現行の引き継ぎへ統合する | 有効な要求・判断・成果・残件 |
| 挨拶・了承・同内容の言い換え | 作業上の意味がなければ削除する | 合意によって変わった条件だけ |
| 現在の目的と無関係な情報 | 作業用情報から外す | 明示された後続依頼があれば、その存在と参照 |
| 不要な秘密情報・個人情報の複製 | 要約へ持ち越さない | 必要な認証方式や保管場所の参照。秘密値そのものは残さない |

参照化は、再開側から実際に参照できることが前提となる。参照先が利用できない場合は、作業に必要な内容を要約内へ残す。

## 削減時にも保持する情報

- 現在の目的、受入条件、明示的な禁止事項、継続的な制約。
- 未完了の要求、未解決の問題、不確実性。
- 正本・owner・作業環境・現在のブランチ・保護すべき既存差分。
- 有効な設計判断と、その判断に必要な理由。
- 完了結果と証拠の参照、証拠が無効になる条件。
- 進行中の処理、未確定の外部操作、データ保全・復旧に必要な状態。
- 次に行う作業と、その前提・依存関係。

継続的な制約は、一つの作業が完了しただけでは失効しない。未確認の作業を完了扱いにして削除しない。認証・policy・安全性に関する制約を、重複や冗長さを理由に弱めない。

例: 「テストを実行せよ」が完了した場合、その命令を「対象変更のテストは成功。対象環境・証拠は指定記録。関連変更があれば再検証」に置き換える。これにより、不要な再実行を避けながら検証根拠を維持する。

## 今回の観測と一般化の限界

| 項目 | 確認できた内容 | 限界 |
|---|---|---|
| Qwenの容量削減 | 2026年9月22日03:34 UTCに完了した圧縮の前後で、通常要求のinputは91,004から30,204tokensへ減少した | 要約要求自体の使用量とは別の値。意味的品質の保証にはならない |
| Qwenの要約内容 | 大規模検査をStep20後へ延期する方針と、途中で広範な再検査を行う次工程が同じ要約に残った | 元の履歴の矛盾を持ち越したのか、圧縮時に撤回を取り落としたのかは未分離 |
| Astraとの共通性 | 利用者の方針として、Astra・Qwen共通の改善対象に設定した | Astraでも同じ要約不整合が実際に発生したとの確認はない。同一設定でのモデル比較も未実施 |
| 改善の実装状況 | 削減対象と保持条件を整理した | 圧縮前の自動整理処理が実装・検証済みという意味ではない |

圧縮頻度、圧縮後の残量、要約の正確さ、作業の再実行は別の評価項目として扱う。バージョン差だけで圧縮方式や品質の差を説明しない。

## 適用範囲と進め方

1. 現行の要求と明示的な訂正から、撤回・完了・継続・未完了を識別する。
2. 私たちが管理する監督指針、再開プロンプト、作業記録、ツール出力を整理する。
3. 整理した内容が、実際にモデルへ渡る入力へ反映されるか確認する。
4. 圧縮後の指示整合性、残件・成果の保持、トークン量、再調査・再実行を測る。

OpenAI提供のCodex本体・内部圧縮処理は変更しない。公式に提供される設定・拡張機能の利用可否を確認し、その範囲で適用する。保存されたセッションログの直接書換えやGatewayでの無差別な履歴削除を、既定の解決策としない。Backend/Gatewayの変更は、その変換に不具合が確認された場合に対象を限定する。
